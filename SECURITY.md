# Security · исследовательский MVP v0.2

Этот проект **не следует применять для сбора корпоративных инвентаризационных данных** без разрешения владельца инфраструктуры и согласования с IT/ИБ.

## Признанные риски

1. **Нет BLE pairing/PIN/аутентификации.** Любое устройство в зоне действия, способное подключиться к открытой GATT-службе, потенциально может запросить последний отчёт. Нельзя гарантировать конфиденциальность и подлинность удалённого клиента.
2. Отчёт может содержать имя рабочей станции, IP, MAC, модели оборудования, доменные и сетевые параметры. Эти поля могут быть служебной информацией.
3. Файл `/report.json` остаётся в энергонезависимой памяти после отключения питания. Это не защищённое хранилище. Физический доступ к плате может раскрыть отчёт.
4. В v0.2 USB HID вводит фиксированную команду запуска PowerShell после BLE RUN. **BLE не требует аутентификации**, поэтому любое соседнее BLE-устройство с доступом к GATT может попытаться запустить этот ввод на разблокированном ПК. В корпоративной среде это существенный риск. Устройство может блокироваться Device Control.
5. PowerShell-сборщик выполняется по явной команде «Старт» в BLE-панели и только на ПК, где у оператора есть право проводить диагностику. Команда видима в Windows и **не обходит** UAC или Execution Policy.

## Минимизация рисков в v0.1

- Никакого Wi-Fi, HTTP endpoint, телеметрии и облачного бэкенда.
- Не считываются пароли, токены, ключи, браузерные профили, файлы пользователей.
- Серийные номера BIOS/платы выключены по умолчанию (`-IncludeSerialNumbers` опционален).
- Параметры PnP ограничены по числу элементов (с признаком `truncated`).
- Страница имеет CSP, пользовательские строки отображаются через `textContent`.
- Максимум отчёта — 64 KiB; USB-передача проверяет CRC32 и размер; BLE повторяет кадры и проверяет CRC32 в браузере.
- При вставке USB ничего не запускается. После BLE RUN записывается проверенный SHA-256 PS1 в `%TEMP%`, затем штатно выполняется, а собранный отчёт сохраняется в `%TEMP%\AdminToolkit-Reports`. Данные не отправляются на сеть; действие не полностью read-only из-за локальных временных файлов.

## Что требуется до использования в производственной сети

Физическое подтверждение на кнопке, отдельная прикладная аутентификация/шифрование или согласованный защищённый транспорт, стирание отчётов и политики хранения, модель прав доступа, регистрация прибора в инвентаризации корпоративных USB, согласование диагностического сборщика, проверка подписи поставляемого кода, тесты перебоев питания и восстановления.

**Важная граница:** CRC32 обнаруживает случайную порчу при передаче, но **не обеспечивает** криптографическую защиту от вмешательства.

## Особый риск v0.2 (BLE RUN + HID)

На этапе MVP пользователь сознательно исключил PIN, pairing, bonding и аутентификацию. BLE RUN даёт возможность инициировать ввод в Windows. Пока не добавлена прикладная авторизация или физическое подтверждение, **не оставляй устройство подключённым к разблокированному корпоративному ПК без непосредственного контроля**. Рекомендуется сначала проверять только на изолированной тестовой машине. Для производственного применения необходимо согласовать список команд, контроль происхождения прошивки и возможность отключения HID.

Windows загрузчик принимает только единственный COM-порт Espressif VID_303A и проверяет SHA-256 сборщика, однако SHA в неизменённой прошивке обеспечивает контроль целостности, а не аутентичность внешнего устройства. Исполнение штатного PS1 подчиняется корпоративным политикам; скрипт может быть заблокирован.
