# ESP32-S3 Admin Toolkit · v0.4.0 (Fast / Full)

## Быстрая инвентаризация и расширенная диагностика (v0.4.0)

В панели «Диагностика» выбирается режим **Быстрая инвентаризация** (по умолчанию) либо **Расширенная диагностика**. Первый собирает только ОС, CPU, RAM, диски, GPU, физические сетевые карты, их MAC, IPv4, шлюзы, DNS, DHCP, локальных администраторов и состояние брандмауэра. Не запрашивает списки PnP, установленных программ, обновлений, служб и событий Windows. Второй сохраняет расширенный набор, но исключает большинство скрытых сетевых адаптеров и повторяющихся HID-устройств.

Сетевые IP/DNS собираются посредством CIM `Win32_NetworkAdapterConfiguration` с сопоставлением `InterfaceIndex` физических интерфейсов (`Get-NetAdapter -Physical`), а не через один общий `Get-NetIPConfiguration`. Если подсистема недоступна, это отображается как ошибка, но не означает отсутствия MAC/IP у компьютера.

BLE использует 16-байтные кадры и групповое подтверждение каждых четырёх кадров (`W4` в метаданных) вместо отдельного подтверждения каждого. Есть повторная отправка группы и итоговый CRC32. Веб-код сохраняет поддержку старых прошивок без `W4`. **Результат и скорость на реальной плате нужно проверить**. Для работы нового режима требуется обновление прошивки: один только веб-интерфейс не меняет сборщик и протокол устройства.

Остаётся прежнее требование ручного переключения раскладки Windows на ENG и явного нажатия «Старт» на телефоне. Без Wi-Fi, PIN, сетевой отправки отчётов и записи JSON/TXT на ПК. Не применять к корпоративным машинам без разрешения IT/ИБ и защиты BLE.

# ESP32-S3 Admin Toolkit · Web v0.3.9 / firmware v0.3.8

Независимый **BLE-only** прототип объединённого USB-прибора: беспроводная клавиатура и мышь (основной режим) плюс опциональная диагностика Windows для **LILYGO T-Dongle-S3 V1.1** (ESP32-S3, 16 MB flash, без PSRAM, ST7735 80×160). Проект **не является форком** и не изменяет существующую беспроводную клавиатуру.

**Схема:** Windows PowerShell (запуск по кнопке в BLE-панели через USB HID) → USB CDC → LittleFS на ESP32-S3 → BLE GATT Notify → Android Chrome (GitHub Pages / локальный HTTPS).

**Что работает по исходному коду:** диагностика Windows 10/11, экспорт JSON и TXT на компьютере, последовательный протокол передачи с CRC32, приём отчёта во Flash, BLE RX/TX с подтверждением пакетов, браузерная панель со скачиванием JSON/TXT, клавиатура с кириллицей и мышь. Реальная работа на физическом устройстве **не проверена** до проведения испытаний.

## Онлайн-установка через браузер (без PlatformIO на компьютере)

Открой [установщик Admin Toolkit](https://labeckiys.github.io/ESP32-S3-Admin-Toolkit/install.html) в **Chrome/Edge на Windows ПК**. Отключи T-Dongle-S3, удерживай BOOT при подключении, отпусти и нажми «Установить Admin Toolkit». Выбери порт **USB JTAG/serial debug unit**. После завершения отключи и вставь плату заново обычным способом.

Установщик использует ESP Web Tools по USB Web Serial. GitHub Actions автоматически компилирует прошивку PlatformIO, собирает единый образ ESP32-S3 (bootloader + partition table + OTA data + firmware), формирует манифест и публикует их вместе с веб-панелью на GitHub Pages. Flashing **заменяет** старую v11.1; откат возможен через [предыдущий установщик клавиатуры](https://labeckiys.github.io/Wireless_keyboard_for_phone-ESP32-T-Dongle-S3/web/index.html).

**Важно:** первый аппаратный запуск Admin Toolkit v0.3 не проверен. Сначала тестовый ПК, без корпоративных сведений. Не отключай плату при прошивке. Веб-установщик нужен только для прошивки через USB; после установки панель работает по BLE без Wi-Fi/PIN.

### Если ESP Web Tools показывает «Failed to initialize»

Онлайн-установщик Admin Toolkit использует **тот же локальный ESP Web Tools 10.4.0 / no_reset**, который работает с клавиатурой v11.1. Он **не сбрасывает T-Dongle-S3 после выбора USB-порта**. Введи плату в ROM Download Mode **вручную**: отключи её от USB, удерживай BOOT при подключении, дождись серого экрана, отпусти BOOT, затем нажми кнопку установки и выбери `USB JTAG/serial debug unit`. Если загрузчик не отвечает, закрой программы, занимающие COM-порт, и повтори. Модуль веб-установщика включён в репозиторий вместе с Apache-2.0 лицензией. Это исправление интерфейса загрузки, а не подтверждение исправности аппаратной работы новой прошивки.

## Текстовый технический паспорт и расширенный аудит v0.3.8 / Web v0.3.9 (2026-11-17)

После завершения BLE-передачи отчёт отображается в одном **выделяемом текстовом поле** с кнопкой «Копировать весь отчёт». Кнопки скачивания TXT/JSON и разделы с сырой JSON-структурой удалены. На Windows сборщик больше не создаёт ни `.txt`, ни `.json` файлов отчёта. Технически JSON сохраняется внутри ESP32 LittleFS для проверки и повторной передачи, и конвертируется в обычный текст в браузере; временный исполняемый PowerShell-сборщик по-прежнему пишется в `%TEMP%`, это не отчёт.

В инвентаризацию добавлены **локальные учётные записи**, отдельные члены групп **Администраторы**, **Пользователи**, **Удалённый рабочий стол** и **Операторы архива**, тип/источник участников и SID, текущий токен администратора; **MAC всех найденных сетевых интерфейсов**, присутствующие PnP-устройства, установленные программы, обновления, остановленные автослужбы, антивирусные продукты, UAC, TPM, Secure Boot, BitLocker. Остальные ранее существовавшие разделы сохранены. Поля и ограничения — в [docs/INVENTORY_FIELDS.md](docs/INVENTORY_FIELDS.md).

Поле `PasswordRequired` означает только требование пароля со стороны Windows; оно **не доказывает, что пароль действительно установлен**. История `PasswordLastSet` — косвенная. Никаких паролей, хешей, Wi-Fi-ключей, сертификатов и секретных данных не извлекается. Вложенные доменные группы и фактические права доменных учётных записей не вычисляются. Часть запросов на рабочем ПК без прав администратора может быть недоступна; статус явно помечается. Данные идентификации ПК передаются по BLE без PIN/аутентификации, поэтому не использовать на корпоративных компьютерах без согласования защиты и IT/ИБ.

**Ограничение:** 65 536 байт на сохранённый отчёт ESP32; большие PnP/списки ПО усекаются с указанием числа записей. После изменений в PowerShell требуется новая прошивка v0.3.8, одного обновления веб-страницы недостаточно. Проверь сначала на тестовом ПК.

## Клавиатура: упрощение интерфейса Web v0.3.8 (2026-11-17)

- На вкладке «Клавиатура» удалён журнал клавиатуры, включая надпись «Ожидается подключение BLE». Диагностический журнал **на вкладке «Диагностика» сохранён**, ошибки клавиатуры при необходимости видны в консоли Chrome.
- Тачпад: короткое касание — левый клик, перемещение — движение курсора; **долгое удержание не вызывает никаких кликов**. Кнопки «Левая», «Правая», «Средняя» и прокрутка остаются независимыми.
- Подавлено стандартное контекстное меню Chrome при долгом касании тачпада; сохранён `touch-action: none`.
- При активном BLE соединении кнопка переименовывается из «Подключить ESP32» в **«Отключить ESP32»**, и повторное нажатие действительно разрывает GATT. При потере связи возвращается «Подключить ESP32». При поиске она временно отключается.
- Эта версия меняет только веб-страницу на GitHub Pages. **Перепрошивка ESP32 не требуется**: устройство может оставаться на firmware v0.3.7.

## Восстановление BLE после завершения диагностики v0.3.7 (2026-11-17)

В аппаратном тесте Windows успешно передала отчёт ESP32 (11 040 байт), но при завершении PowerShell-сборщика BLE соединение с телефоном пропало, иногда до переподключения USB. Предполагаемая причина — CDC-сигналы DTR/RTS при закрытии COM-порта: Arduino TinyUSB содержит обработчик программного входа в загрузчик.

- Перед USB.begin() выполнено `Serial.enableReboot(false)`, чтобы DTR/RTS не перезагружали устройство во время работы; ручной вход через BOOT остаётся доступным
- После реального BLE-разрыва реклама возобновляется через 500 мс, затем повторяется через 3 с и каждые 10 с до подключения
- Встроенный PowerShell и USB-протокол передачи отчётов сохранены без изменений
- Прибор продолжает хранить последний отчёт в LittleFS; повторное подключение телефона не должно требовать повторного сканирования Windows

Первопричина ещё не подтверждена аппаратным тестом новой прошивки. Если звезда появляется снова сразу после завершения отчёта — произошла перезагрузка, если экран сохраняется и пишет `BLE: waiting` — необходимо проверять рекламу BLE.

## Исправление USB CDC v0.3.5 (2026-11-17)

Ошибка `Порт 'COM4' не существует` возникала при повторном открытии CDC после получения диагностического PowerShell-скрипта. Теперь скрипт и готовый отчёт передаются через **одно открытие COM-порта**. Исходный bootstrap держит порт открытым, передаёт объект SerialPort сборщику и закрывает его в конце работы в `finally`. Отдельный ручной запуск сборщика с `-Port COM7` остаётся совместимым.

Новая версия сборщика и SHA-256 встроены в прошивку. Для применения необходима повторная прошивка ESP32, одно обновление веб-страницы не помогает. На физическом ПК исправление ещё не проверялось.

## Выбор раскладки для диагностики v0.3.4

В разделе «Диагностика» есть переключатель состояния языка на компьютере. Он **не управляет языком Windows**. Если ENG уже установлена вручную, выбери ENG в панели и нажми «Старт диагностики»; ESP32 введёт команду PowerShell без каких-либо переключений. При RUS кнопка «Старт» заблокирована: сначала выбери ENG на компьютере, затем укажи ENG на телефоне.

Такое поведение надёжнее старого автопереключения v0.3.3: USB HID не может определять раскладку, а Win+Space перебирает их в непредсказуемом порядке при нескольких языках. Старый `RUN|RU` не переключает язык и отклоняется. Кодировка кириллицы в отчётах PowerShell обрабатывается независимо от раскладки.

## Исправления дисплея v0.3.2 (2026-11-16)

- Устранено мигание TFT: полный экран больше не очищается каждые 900 мс; изменяются только нужные строки статуса.
- При включении отображается графическая заставка с микросхемой S3 приблизительно 1,2 с. Старая прошивка v0.2.0 на плате сама не обновится — требуется повторная прошивка через установщик.

## Без автоматического переключения языка v0.3.4 (2026-11-17)

- При запуске PowerShell ESP32 больше **не нажимает Win+Space**. Windows сохраняет выбранную оператором раскладку.
- В панели диагностики явно выбирается текущая раскладка. **ENG** разрешает команду запуска, а **RUS** блокирует запуск и предлагает вручную переключиться на ENG.
- Старая команда `RUN|RU` безопасно отклоняется прошивкой с `N|ENG_REQUIRED`; она не отправляет переключение и не пытается вводить PowerShell кириллицей.
- В режиме клавиатуры отдельная кнопка ручного переключения остаётся доступной.
- Выбор в браузере не меняет язык Windows: USB HID не умеет достоверно узнавать текущую раскладку. Перед запуском убедись, что на ПК действительно ENG.

## Исправления после аппаратного теста (2026-11-16)

- **Windows PowerShell 5.1:** при доставке диагностического скрипта через USB bootstrap после проверки SHA-256 добавляет UTF-8 BOM к временной `.ps1`; PowerShell 5.1 теперь корректно декодирует кириллицу. Исправление требует **повторной прошивки ESP32**.
- **BLE-мышь:** движения курсора идут через `writeValueWithoutResponse`, если браузер и характеристика поддерживают его. Ожидающие перемещения объединяются, очередь ограничена (нет накопления старой траектории).
- Английское системное окно Bluetooth с кнопкой **PAIR** принадлежит Chrome/Android, не сайту; оно разрешает доступ страницы к BLE, без PIN и системного bonding.

## Единая панель v0.3

**Клавиатура — стартовая вкладка.** После открытия страницы по HTTPS показывается интерфейс ввода текста, быстрые клавиши (включая копирование и переключение раскладки), сенсорная мышь и чувствительность. Вторая вкладка «Диагностика» содержит «Старт», получение отчёта, копирование, экспорт TXT/JSON. BLE-подключение общее для обеих вкладок.

Данные клавиатуры отправляются через BLE пакетами `0x10 + UTF-8` по 19 байт полезной нагрузки, с подтверждением набора каждого пакета. Команды клавиш (`K|...`) и мыши (`0x02`) отделены от диагностических команд (`RUN`, `GET`, `START` и т. п.). На USB представлены HID-клавиатура, HID-мышь и CDC для отчётов.

Новая веб-страница **не добавляет возможности старой прошивке**. Для единой панели нужна прошивка Admin Toolkit v0.3 на ESP32-S3. Исходный репозиторий клавиатуры v11.1 остаётся без изменений. Первое руководство: [QUICKSTART-v0.3.md](QUICKSTART-v0.3.md).

## Ограничения MVP

- Без Wi-Fi, PIN, BLE pairing/bonding и облачной передачи.
- При простом подключении USB ничего не выполняется. После нажатия «Старт диагностики» в веб-панели ESP32 вводит фиксированную команду в видимом окне PowerShell по USB HID **только при выбранной оператором ENG раскладке**; язык Windows автоматически не переключается. Нужен разблокированный рабочий стол; запуск может быть заблокирован политиками организации.
- Максимальный отчёт — **65 536 байт**, одна сохранённая копия на ESP32.
- Передача BLE 16 байт полезной нагрузки на кадр с подтверждением каждого кадра: потенциально медленная, зато совместима с ATT MTU 23.
- Состояние SSD SMART, точный SSID Wi-Fi, полный аудит и часть параметров безопасности не гарантируются: сборщик отмечает ошибки и отсутствие данных.
- Windows и USB CDC могут потребовать установки/настройки драйвера или разрешения корпоративной политики; **никаких обходов защит**.
- **Важно:** без аутентификации и шифрования BLE данные и команда выдачи отчёта доступны для атак поблизости. Не используй с реальными корпоративными сведениями до согласования защиты.

## Сборка прошивки

1. Установи VS Code и PlatformIO.
2. Открой **папку `firmware/`**, а не корень репозитория.
3. Запусти `pio run` или Build в PlatformIO.
4. Не прошивай рабочий донгл до проверки: сначала сохрани образ текущей клавиатуры и используй тестовую ESP32, либо обеспечь возможность восстановления.
5. Для входа в режим загрузчика удерживай BOOT (GPIO0) при подключении и затем выполняй Upload.
6. После прошивки подключи устройство заново обычным способом.

Конфигурация: PlatformIO `espressif32@6.12.0`, Arduino, TinyUSB CDC на загрузке, USB HID для запуска через явную команду RUN, LittleFS, BLE, дисплей ST7735. `firmware/platformio.ini` использует отдельную таблицу разделов `partitions.csv`.

## Дополнительный сценарий диагностики — запуск с телефона без установки агента

1. Открой Windows 10/11 в разрешённой разблокированной пользовательской сессии и убедись, что нет модального окна или UAC, перехватывающего ввод. В веб-панели укажи текущую раскладку RUS или ENG; если установлены более двух раскладок, вручную выбери ENG на Windows.
2. Вставь T-Dongle-S3 в USB. Должны появиться HID-клавиатура и виртуальный CDC COM-порт. Подожди завершения определения устройства.
3. Открой панель на Samsung Galaxy S25 Ultra в Android Chrome по HTTPS и нажми **«Подключить ESP32»**.
4. Нажми **«Старт диагностики»**. Именно теперь, **не сразу после вставки USB**, ESP32 отправит Win+R, откроет видимый PowerShell и напечатает ограниченную диагностическую команду. Отдельный агент на Windows не требуется.
5. PowerShell найдёт единственный CDC COM-порт с Espressif USB VID 303A, запросит у ESP32 локально встроенный PowerShell-сборщик, сравнит его SHA-256 с зашитой константой и сохранит во временной папке Windows. Запустит сборщик штатным способом **без обхода Execution Policy**.
6. Сборщик соберёт JSON **в памяти**, отправит его через CDC в ESP32, а телефон автоматически запросит данные по BLE и покажет текстовый технический паспорт для копирования. Файлы отчёта на Windows и телефоне не создаются.

**Ограничения:** если Windows работает с русской раскладкой, Powershell/набор команды через HID может не сработать. Открытие PowerShell и сбор инвентаризации блокируются некоторыми корпоративными политиками; не обходи их. Если COM-порт не виден, если VID/PID отличается или найдено несколько устройств Espressif, bootstrap завершится с видимой ошибкой. **Никогда не запускай на производственных ПК без согласования с IT/ИБ.**

Технически PowerShell получает код с внешнего USB-устройства и выполняет его; доверять стоит только собственной проверенной и прошитой плате. До аппаратного теста это экспериментальный сценарий, не подтверждённая работающая функция.

## Первый тест Windows — сначала без донгла

Из Windows PowerShell 5.1 (не обязательно от администратора):

```powershell
cd <папка_проекта>\collectors\windows
.\Collect-Inventory.ps1 -NoTransfer
```

Скрипт выполнит только сбор данных в памяти и выведет размер отчёта и CRC32; TXT/JSON файлы отчёта не создаются. Никаких запросов в интернет и изменений конфигурации он не делает. Если PowerShell не разрешает запуск по корпоративной политике, согласуй этот запуск с IT-службой; **не обходи политику**.

## Пробная передача на ESP32

1. Подключи прошитый донгл к **разблокированному тестовому ПК** с Windows.
2. Открой «Диспетчер устройств → Порты (COM и LPT)» и найди USB Serial Device/ESP32 CDC — запиши номер, например `COM7`. Если порт отсутствует, остановись и проверь USB-дескрипторы/драйверы.
3. В каталоге `collectors\windows` запусти:

```powershell
.\Collect-Inventory.ps1 -Port COM7
```

4. Дождись сообщения об успешной передаче. При ошибке файлы отчёта не создаются; повтори безопасную диагностику после выяснения причины.
5. Открой веб-панель на Android Chrome через **HTTPS**. После публикации через GitHub Pages ожидаемый URL: `https://labeckiys.github.io/ESP32-S3-Admin-Toolkit/` (ссылка заработает только после создания репозитория и настройки Pages).
6. Нажми **Подключить ESP32** → выбери `AdminToolkit-S3` → **Получить отчёт**. Панель покажет прогресс, проверит длину и CRC32, выведет технический текст и позволит скопировать его.

**Важно:** открытие `web/index.html` через `file://` не поддерживает Web Bluetooth. Для локальных тестов нужен надёжный HTTPS origin либо `localhost` с соответствующей настройкой браузера.

- `SECURITY.md` — ограничения безопасности, модель угроз.

Разработан с нуля на основе официальных интерфейсов; аппаратная раскладка соответствует документации LILYGO. Старый проект https://github.com/LabeckiyS/Wireless_keyboard_for_phone-ESP32-T-Dongle-S3 упомянут только как референс.

## Встраивание сборщика в прошивку

При сборке PlatformIO скрипт `firmware/extra_scripts/embed_collector.py` добавляет в заголовочный файл `firmware/include/generated_collector.h` Base64-копию одобренного `collectors/windows/Collect-Inventory.ps1` и формирует SHA-256, зафиксированный в команде загрузчика. При изменении PowerShell-кода необходимо пересобрать прошивку и повторно проверить сборщик. Не подменяй файл после сборки.

В v0.2 HID-путь вводит до ~1k ASCII-символов и требует стабильного устройства ввода и фокуса. Длительность запуска зависит от Windows; проверка производилась только статическими тестами, на реальном ПК нужно подтвердить раскладку, скорость печати и USB CDC-идентификацию.
